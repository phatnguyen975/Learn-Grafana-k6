## 1. Column Schema

| Column   | Type   | Required | Format / Constraints                                                                        | Source    |
| -------- | ------ | -------- | ------------------------------------------------------------------------------------------- | --------- |
| name     | string | Yes      | Any string, e.g. `Perf User {index}`                                                        | generated |
| email    | string | Yes      | Must be strictly unique format: `perf_{unix_timestamp}_{zero_padded_index}@stress.test`     | generated |
| password | string | Yes      | Minimum 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special char (e.g. `StressTest123!`) | static    |

**Column sources:**

- `credentials` = obtained from auth strategy (email/password for login, token for Strategy 3)
- `db_seeded` = real ID created by `seed-data.js` and read back from the API
- `generated` = synthetic value that does not require a DB lookup (e.g. generated email pattern)
- `static` = same value on every row (e.g. fixed quantity or price)

## 2. Row Count Calculation

**Data consumption category:** Category B — Write-once rows

_(Because POST /api/register creates a unique user, every iteration must use a fresh email to avoid FR-01 duplication errors)._

**Calculation:**

```
test_type = stress
peak_vus = 53
test_duration_seconds = 10 * 60 = 600   (5 steps × 2 min, ignoring ramp-down)
avg_response_time_seconds = 0.0198      (baseline p50 = 19.82ms)
think_time_seconds = 0.75               (from workload model)

iterations_per_vu = floor(600 / (0.0198 + 0.75)) = floor(600 / 0.7698) = floor(779.42) = 779
total_iterations  = 53 × 779 = 41,287
recommended_rows  = ceil(41,287 × 1.30) = 53,673.1  →  generate 54,000 rows
```

| Variable                  | Value      | Source                             |
| ------------------------- | ---------- | ---------------------------------- |
| peak_vus                  | 53         | `test-plan.md`                     |
| test_duration_seconds     | 600        | `test-plan.md`                     |
| avg_response_time_seconds | 0.0198     | `perf-config.json baseline.p50_ms` |
| think_time_seconds        | 0.75       | `test-plan.md`                     |
| iterations_per_vu         | 779        | Calculated                         |
| total_iterations          | 41,287     | Calculated                         |
| buffer_factor             | 1.30       | 1.30 (Category B)                  |
| **recommended_rows**      | **54,000** | **Final value**                    |

## 6. Cleanup Procedure

To remove test data created during this stress test using the API:

1. Obtain an Admin JWT token by logging in to `POST /api/login` with admin credentials (`admin@eshop.com` / `Admin123!`).
2. Fetch all users via `GET /api/admin/users`.
3. Filter the returned list for users where `email` ends with `@stress.test`.
4. Iterate over the filtered list and call `DELETE /api/admin/users/:id` for each user.

_(You can write a simple Node.js script using `axios` or `fetch` to automate this cleanup process instead of interacting directly with the database)._
